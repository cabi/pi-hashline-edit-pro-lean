# MAINTENANCE

## Upstream version

Pinned to `pi-hashline-edit-pro@6.4.8` (exact pin, no `^`) in `package.json`. Upstream is a regular dependency: never copied, never patched; `node_modules` must stay untouched.

Sync 6.4.7 → 6.4.8: no tools added or removed and no tool-prompt (description/snippet) changes — the default-config capture in `upstream-inventory.json` is byte-identical. All prompt-facing changes are codemode-only: a codemode `read` now resolves to the file's plain text by default (like the built-in `read`), and a new optional `anchors: true` boolean — present in the `read` schema only in codemode sessions (`buildReadToolSchema(flags.codemode)` in `src/read.ts`) — opts back into `{ text, lines, notices }`; the read script guideline was rewritten accordingly, and the result-contract guideline now prefixes the enabled op names (`resultContractGuideline(flags)` in `src/edit-common.ts`) but still attaches via `read` only, so pi's `buildRules` dedupe is unchanged. Lean mirrors this in `CODEMODE_READ_RESULTS_RULE` and the `anchors` field of the merged `HASHLINE_SCHEMA`; the standalone `read` schema picks the param up automatically from the captured codemode registration. The rest of 6.4.8 is internal and flows through the forwarded tools: anchor-carry propagation for insert/copy/move (batch and preview paths included), anchored-diff spans now split around interior unchanged lines (`splitPlacedSpan`), stack-safe `spliceAll` for large edits, `mintAnchor` fixes for exhausted-alphabet sessions, an `assertLineCount` guard at anchor allocation, and a `renderReadCall` rewrite (UI-only). Internals 1–10 below re-verified; upstream's root `index.ts` is unchanged.

## What was trimmed, per tool

Upstream originals are captured in `upstream-inventory.json` (regenerate with `npx tsx scripts/inventory.ts`). Lean texts live in `src/lean-text.ts` and are flag-aware (config/codemode), mirroring upstream's prompt assembly in `src/edit-common.ts` (since 6.4.7 the `with*Prompts` helpers assemble directly; the shared edit guidelines attach only via `replace` — pi's `buildRules` dedupe makes the combined prompt identical).

- **read** (upstream 641 ch): kept how anchors work, `offset`/`limit` usage (6.4.6 corrected the anchor-`limit` wording — `limit` counts from the anchor row inclusive — and the lean text matches), the always-anchor/never-JSON facts, and the no-anchors-means-gated-model note. Dropped repetition of schema types, UI-only notes, and re-explanations of replace semantics.
- **hashline** (merged; replaces `replace_match` 805 + `insert` 217 + `copy` 358 + `move` 317 + `grep` 808 + `undo_last_change` 257 ch): one-line bullets per op, disabled ops omitted from the text; boundary-row, destination-`anchor`+`direction`, and append-at-end notes for copy/move kept; the `grep` bullet documents the `lineNumber:│`/`lineNumber-│` row format; since 6.4.2 the `replace_match` bullet also carries the fragment-only `old_string` contract (never text `new_string` leaves unchanged; whole-line/whole-range changes go to `replace` with the same anchors). Full originals remain available to the model via `op: help`.
- Parameter schemas: `src/index.ts` `stripParamDescriptions()` walks the captured TypeBox schema and deletes `description` keys only — types, enums, bounds, and required stay. The merged tool keeps every field optional (union of upstream fields) so validation is upstream's job per op; upstream rejects unknown fields with `[E_BAD_SHAPE]`, same as its per-tool schemas. Since 6.4, `path` on the edit ops is optional-but-checked: absent is fine (anchors resolve the file), present must match the file the anchors own (`[E_BAD_SHAPE]` otherwise) — the lean path guideline says exactly that. `copy`/`move` target a destination `anchor` + `direction` instead of `insert_after`.
- Guidelines: default config 25 deduped upstream rules → 10 lean rules; with codemode active 31 → 15 (adds upstream's script-result rules — the codemode `read` plain-text default with `anchors: true` for `{ text, lines, notices }` (since 6.4.8), edit-op chaining via `anchors[].anchor`/`anchorsOmitted`, `grep` `results[].lines[]` — mirrored as compact lean rules). Kept every rule that changes how the model calls the tools: batching same-file edits, verbatim text/no escape decoding, path rules per `requirePath`, diff reading rules when auto-read is on, codemode contract/transfer/undo rules, the strict-input note (since 6.4.2 strict-input also rejects a `replace_match` `old_string` that covers the whole range or retypes unchanged text, and the shared rule says so), and the `replace_match` scoping strategy (6.4.2+).
## Upstream internals this package depends on

1. **Registered tool names** (`read`, `replace`, `replace_match`, `insert`, `copy`, `move`, `grep`, `undo_last_change`; `src/index.ts` registers lean `read`/`replace` under the same names so upstream's session write-hook batching and undo registry keep matching). 6.4.0 renamed `anchor_grep` → `grep` and registers it under pi's own grep name; lean's hashline `grep` op forwards to the captured definition (anchored flavor normally, pi's vanilla grep when the model is gated or `anchorGrepEnabled` is off — upstream swaps the definition under the same name, like the vanilla-read swap).
2. **`registerTool` replace-by-name semantics + upstream's re-registration waves** (`index.ts` `refreshEditTools`, the model-gate vanilla-read and vanilla-grep swaps, and since 6.4.7 a `refreshEditTools` at `before_agent_start` whenever the codemode tool's presence changed): the Proxy captures every wave into `latest`; lean `execute` always forwards to the most recent definition, so config refreshes and the flavor swaps survive without list changes.
3. **`prepareArguments` contract**: pi runs it before schema validation; lean canonicalizes `op` there, then applies the upstream tool's own `prepareArguments` (anchor-row prefix stripping, `remove_from`↔`replace_from` aliases) inside `forwardExecute` after stripping `op`/`about` (upstream rejects unknown fields, `[E_BAD_SHAPE]`).
4. **Event flow**: lean's `session_start` handler is registered after upstream's, so it runs after; it re-reads `currentEditFlags()` and flushes the shadowed `setActiveTools` list exactly once per session start — minus the name `grep`, which upstream's 6.4 list includes but whose registration lean captures: in the real session the name would resolve to pi's built-in vanilla grep and compete with the hashline `grep` op.
5. **`setActiveTools` call sites** (session_start filtering, `syncModelGate` on `model_select`/`before_agent_start`, config-UI toggles): all captured into the shadow list; `getActiveTools` serves the shadow to upstream so its own logic stays consistent while the real list stays frozen.
6. **Config flags → prompt assembly**: `src/config.ts` `readConfig()` (no cache) at execute time gates disabled ops (`replaceMatchEnabled`, `copyMoveEnabled`; `anchorGrepEnabled` no longer disables anything — it flips the captured `grep` definition to the vanilla flavor); `src/edit-common.ts` `currentEditFlags(codemode)` at session start picks guideline variants; `src/model-gate.ts` `modelDisabled()` + `ctx.model` at execute time enforces `disableOnModels`. Since 6.4.2 upstream's `withReplaceMatchPrompts` pushes an extra strict-input guideline for `replace_match`; lean folds that into the shared `STRICT_INPUT_RULE` instead.
7. **Deep imports** `pi-hashline-edit-pro/src/{config,edit-common,model-gate}.ts` — possible because upstream's `package.json` has no `exports` field. If upstream adds `exports`, switch to whatever public surface replaces them.
8. **`AgentToolResult.details`**: lean stashes `details.leanOp` to dispatch `renderCall`/`renderResult` to the captured upstream renderer of that op.
9. **`structuredFailure`** from `src/structured.ts` for error parity (isError + `structuredContent.error.code`) and **`outputSchema`** merged as an `anyOf` of the captured per-op schemas so codemode keeps getting structured results.
10. **pi framework behavior**: declarations sent to the model are `{name, description, parameters}` only (`outputSchema` is free); `buildRules` dedupes identical guideline strings; prepare → validate → execute order.

## Known deviations (deliberate)

- **Frozen tool list under the model gate**: upstream removes gated tools via `setActiveTools`; lean keeps them visible and refuses at execute time with `E_LEAN_MODEL_GATED` (read serves the vanilla definition when `readOnDisabledModels: "vanilla"`, and the `grep` op always serves the captured vanilla-grep definition — gated models keep a working search). This is step 6 of the lean spec ("the tool list must not change mid-session").
- **Config-UI mid-session text changes** (requirePath/strictInput toggles rewrite upstream descriptions live): lean texts are frozen for the session and refresh at the next `session_start`; execution-level toggles apply immediately.

## How to upgrade

1. Bump the pin in `package.json` and `npm install`.
2. `npm run typecheck` — catches breaks in the deep imports and extension API.
3. `npx tsx scripts/inventory.ts`, then diff the new capture against `upstream-inventory.json` (tool set, names, descriptions, snippets, guidelines, schemas, flags). Commit the regenerated file.
4. Update `src/lean-text.ts` and the schema union in `src/lean-text.ts`/`src/ops.ts` if upstream renamed fields, changed call-affecting rules, or added/removed tools. Keep the trimming rules from the lean spec (each thing once; no restating what the schema says; keep call-affecting rules).
5. `npm test` — the per-op forwarding, gated-model, and frozen-list tests fail loudly if registration or event flow changed.
6. `npm run measure` and update the table in `README.md`.
7. Update the version above and the trim notes in this file.
