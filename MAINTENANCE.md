# MAINTENANCE

## Upstream version

Pinned to `pi-hashline-edit-pro@7.1.1` (exact pin, no `^`) in `package.json`. Upstream is a regular dependency: never copied, never patched; `node_modules` must stay untouched.
Sync 6.5.1 → 7.0.0: no tools or schema fields added or removed — the only schema change is cosmetic (`direction` on insert/copy/move moved from a TypeBox literal union to `{ type: "string", enum }`, the shape `HASHLINE_SCHEMA` already used). Breaking: anchors are now 5-character lowercase instead of 4-character mixed-case (`HASH_LEN` 4→5 in `src/hashline/alphabet.ts`, `HASH_STORE_VERSION` 9→10), so an upgrade from 6.x invalidates existing anchors — hash-store snapshots and undo history are cleared, sidecar anchors are ignored and re-minted on the next read. Anchor slips widened: `parseHashRef` strips surrounding quotes silently, lowercases a case-only mismatch with a `[W_ANCHOR_CASE]` warning (rejected under strict input), and two new anchor-field shapes reduce with `[W_BAD_REF]` (`12:│ abcde│content`, `abcde (line 12)`); `E_STALE_ANCHOR` now distinguishes an anchor that "was valid earlier in this session" from one that "was never served" (new `anchorWasMinted`), and the old case-sensitivity hints are gone. `replace_match`'s `replacement` may now span lines (`src/payload-contract.ts` splits `singleLineFragment` into `singleLineMatch` + `replacementFragment`: a lone break counts as `""` and deletes the match, leading/interior breaks split into lines, new lines inherit the file's line endings), while `match` still must stay within one line. `replace` rejects `match`/`replacement`-style calls with `[E_BAD_SHAPE]` pointing at `replace_match`. `grep` no longer pre-rejects an invalid regex with `[E_BAD_SHAPE]` — ripgrep's own error arrives as `[E_GREP_FAILED]`. The cross-file-move batching rule got a docs-only clarification (`batch.ts` unchanged): a cross-file move whose source file also gets same-message edits runs outside any batch, so send it in a separate message. Internals 1–10 re-verified: root `index.ts`, `config.ts`, `model-gate.ts`, `structured.ts`, `batch.ts`, and every other file lean imports or intercepts is byte-identical to 6.5.1; the changes live in `edit-common.ts`, `hashline/*`, `constants.ts`, `payload-contract.ts`, `replace.ts`, `replace-match.ts`, `grep.ts`, `read.ts`, `write-hook.ts`, `prompts.ts`, and `tool-prompts/*.md`.

Sync 7.0.0 → 7.1.1: 7.1.0 adds the `outline` tool (`src/outline-tool.ts`, `src/outline/*`, vendored tree-sitter WASM grammars) — **opt-in**: config `outlineEnabled` (default `false`), registered unconditionally with `defaultActive: false`, toggled via `/hashline-config`; upstream's `refreshEditTools` now calls `setAnchorToolEnabled(["outline"], config.outlineEnabled === true)`. Params: `path` (file, directory, or glob) and `depth` (0–10, default 2). Rows are the first declaration line of each symbol (top-level declarations plus type/module members, never inside a function body; decorators/annotations sit outside the span); a `[limit N]` line under a row is the span to read, `[N nested]` marks children hidden by `depth`. Caps: 400 rows shared across files (min 20 per file), 50KB per response, files >200KB skipped, batches stop at 400,000 source lines. Supported: JavaScript, TypeScript, JSX/TSX, Python, Go, Rust, Solidity, Java, PHP, Blade, SCSS, Sass, Markdown; anything else (or symbol-less) falls back to a head-and-tail preview. Lean adaptation: the op lives under the hashline umbrella — the session_start flush also drops the name `outline` (the registration is captured like the rest), and the op refuses with `E_LEAN_OP_DISABLED` until the config switch is on; the merged schema gained `outline` in the enum plus `depth`; the description bullet, snippet entry, prefer-rule entry, usage guideline, and codemode results rule appear only while enabled. Also mirrored: the codemode contract rule gained "Arguments that fail the tool's schema still throw before the tool runs." 7.1.1 is fixes only: `grep` maps hits back to physical lines for CRLF/CR files, clipped (>200ch) lines are no longer served/editable (the stale-anchor refusal now says "Line X is clipped above and not editable from here; call read() before editing."), `undo_last_change` reports `[E_NOT_FOUND] File not found: ...` when the file disappeared instead of reverting, and outline's directory/glob handling was refined. Internals 1–10 re-verified against 7.1.1; `EditToolFlags` gained `outlineEnabled` and the gated-op preference list now starts `read, outline, replace, replace_match, …`.
## What was trimmed, per tool

Upstream originals are captured in `upstream-inventory.json` (regenerate with `npx tsx scripts/inventory.ts`). Lean texts live in `src/lean-text.ts` and are flag-aware (config/codemode), mirroring upstream's prompt assembly in `src/edit-common.ts` (since 6.4.7 the `with*Prompts` helpers assemble directly; the shared edit guidelines attach only via `replace` — pi's `buildRules` dedupe makes the combined prompt identical).

- **read** (upstream 635 ch): kept how anchors work, `offset`/`limit` usage (6.4.6 corrected the anchor-`limit` wording — `limit` counts from the anchor row inclusive — and the lean text matches), the always-anchor/never-JSON facts, and the no-anchors-means-gated-model note. Dropped repetition of schema types, UI-only notes, and re-explanations of replace semantics.
- **hashline** (merged; replaces `replace_match` 772 + `insert` 175 + `copy` 333 + `move` 478 + `grep` 796 + `undo_last_change` 257 ch; 7.0.0 lengthened replace_match for the multi-line replacement contract and move for the cross-file-move batching note; 7.1.0 adds `outline` 1683 ch): one-line bullets per op, disabled ops omitted from the text; anchors are the 5-character lowercase codes (7.0.0) from `read`/`grep` rows; boundary-row, destination-`anchor`+`direction`, and append-at-end notes for copy/move kept; the `grep` bullet documents the `lineNumber:│`/`lineNumber-│` row format; the `replace_match` bullet uses the `match`/`replacement` fields (renamed in 6.5.0) and carries their contracts: fragment-only `match` (never text `replacement` leaves unchanged), `match` stays within one line while `replacement` may span lines (7.0.0: a lone break deletes, leading/interior breaks split into lines, new lines inherit the file's line endings), narrow the anchors to select occurrences, whole-line changes go to `replace` with the same anchor; the `outline` bullet (7.1.0, dense single row: header format, `[limit N]` span reads, `[N nested]`/`depth`, the caps, the preview fallback, clipped rows not editable) appears only while `outlineEnabled` is on. Full originals remain available to the model via `op: help`.
- Parameter schemas: `src/index.ts` `stripParamDescriptions()` walks the captured TypeBox schema and deletes `description` keys only — types, enums, bounds, and required stay. The merged tool keeps every field optional (union of upstream fields) so validation is upstream's job per op; upstream rejects unknown fields with `[E_BAD_SHAPE]`, same as its per-tool schemas. Since 6.4, `path` on the edit ops is optional-but-checked: absent is fine (anchors resolve the file), present must match the file the anchors own (`[E_BAD_SHAPE]` otherwise) — the lean path guideline says exactly that. `copy`/`move` target a destination `anchor` + `direction` instead of `insert_after`.
- Guidelines: default config 24 deduped upstream rules → 10 lean rules; with codemode active 30 → 15 (adds upstream's script-result rules — the codemode `read` plain-text default with `anchors: true` for `{ text, lines, notices }` (since 6.4.8), edit-op chaining via `anchors[].anchor`/`anchorsOmitted`, `grep` `results[].lines[]` — mirrored as compact lean rules). Kept every rule that changes how the model calls the tools: batching same-file edits (since 6.5.0 with the send-edits-together nudge), verbatim text/no escape decoding, path rules per `requirePath`, diff reading rules when auto-read is on (since 6.5.0 plus "rows the diff does not show keep their anchors"), codemode contract/transfer/undo rules, the generic strict-input note (since 6.5.0 strict-input no longer rejects `replace_match` retype/whole-range inputs — that upstream behavior was removed; 7.0.0 adds the anchor-case auto-lowercase `[W_ANCHOR_CASE]` to the strict-input rejections), and the `replace_match` scoping strategy (narrow the anchors to select occurrences).
## Upstream internals this package depends on

1. **Registered tool names** (`read`, `replace`, `replace_match`, `insert`, `copy`, `move`, `grep`, `undo_last_change`, and since 7.1.0 `outline` — opt-in, registered unconditionally with `defaultActive: false`; `src/index.ts` registers lean `read`/`replace` under the same names so upstream's session write-hook batching and undo registry keep matching). 6.4.0 renamed `anchor_grep` → `grep` and registers it under pi's own grep name; lean's hashline `grep` op forwards to the captured definition (anchored flavor normally, pi's vanilla grep when the model is gated or `anchorGrepEnabled` is off — upstream swaps the definition under the same name, like the vanilla-read swap); the hashline `outline` op likewise forwards to the captured outline definition whenever the config switch is on.
2. **`registerTool` replace-by-name semantics + upstream's re-registration waves** (`index.ts` `refreshEditTools`, the model-gate vanilla-read and vanilla-grep swaps, and since 6.4.7 a `refreshEditTools` at `before_agent_start` whenever the codemode tool's presence changed): the Proxy captures every wave into `latest`; lean `execute` always forwards to the most recent definition, so config refreshes and the flavor swaps survive without list changes.
3. **`prepareArguments` contract**: pi runs it before schema validation; lean canonicalizes `op` there, then applies the upstream tool's own `prepareArguments` (anchor-row prefix stripping, `remove_from`↔`replace_from` aliases) inside `forwardExecute` after stripping `op`/`about` (upstream rejects unknown fields, `[E_BAD_SHAPE]`).
4. **Event flow**: lean's `session_start` handler is registered after upstream's, so it runs after; it re-reads `currentEditFlags()` and flushes the shadowed `setActiveTools` list exactly once per session start — minus the names `grep` and `outline`: upstream's 6.4 list includes `grep` but lean captures its registration, so in the real session the name would resolve to pi's built-in vanilla grep and compete with the hashline `grep` op; `outline` (7.1.0) is captured the same way, so the op always lives under `hashline` instead of the session's tool list, whether the config switch is on or off.
5. **`setActiveTools` call sites** (session_start filtering, `syncModelGate` on `model_select`/`before_agent_start`, config-UI toggles): all captured into the shadow list; `getActiveTools` serves the shadow to upstream so its own logic stays consistent while the real list stays frozen.
6. **Config flags → prompt assembly**: `src/config.ts` `readConfig()` (no cache) at execute time gates disabled ops (`replaceMatchEnabled`, `copyMoveEnabled`; `anchorGrepEnabled` no longer disables anything — it flips the captured `grep` definition to the vanilla flavor; `outlineEnabled` since 7.1.0 refuses the outline op with `E_LEAN_OP_DISABLED` until switched on); `src/edit-common.ts` `currentEditFlags(codemode)` at session start picks guideline variants; `src/model-gate.ts` `modelDisabled()` + `ctx.model` at execute time enforces `disableOnModels`. Since 6.5.0 upstream's `withReplaceMatchPrompts` is flag-agnostic — it no longer pushes a strict-input guideline, and strict-input no longer rejects `replace_match` retype/whole-range inputs — so lean's shared `STRICT_INPUT_RULE` is again the full story.
7. **Deep imports** `pi-hashline-edit-pro/src/{config,edit-common,model-gate}.ts` — possible because upstream's `package.json` has no `exports` field. If upstream adds `exports`, switch to whatever public surface replaces them.
8. **`AgentToolResult.details`**: lean stashes `details.leanOp` to dispatch `renderCall`/`renderResult` to the captured upstream renderer of that op.
9. **`structuredFailure`** from `src/structured.ts` for error parity (isError + `structuredContent.error.code`) and **`outputSchema`** merged as an `anyOf` of the captured per-op schemas so codemode keeps getting structured results.
10. **pi framework behavior**: declarations sent to the model are `{name, description, parameters}` only (`outputSchema` is free); `buildRules` dedupes identical guideline strings; prepare → validate → execute order.

## Known deviations (deliberate)

- **Frozen tool list under the model gate**: upstream removes gated tools via `setActiveTools`; lean keeps them visible and refuses at execute time with `E_LEAN_MODEL_GATED` (read serves the vanilla definition when `readOnDisabledModels: "vanilla"`, and the `grep` op always serves the captured vanilla-grep definition — gated models keep a working search). This is step 6 of the lean spec ("the tool list must not change mid-session").
- **Config-UI mid-session text changes** (requirePath/strictInput toggles rewrite upstream descriptions live): lean texts are frozen for the session and refresh at the next `session_start`; execution-level toggles apply immediately.

## How to upgrade

1. Bump the pin in `package.json` and `npm install`.
2. `npm run typecheck` — catches breaks in the deep imports and extension API.
3. `npx tsx scripts/inventory.ts`, then diff the new capture against `upstream-inventory.json` (tool set, names, descriptions, snippets, guidelines, schemas, flags). Commit the regenerated file.
4. Update `src/lean-text.ts` and the schema union in `src/lean-text.ts`/`src/ops.ts` if upstream renamed fields, changed call-affecting rules, or added/removed tools. Keep the trimming rules from the lean spec (each thing once; no restating what the schema says; keep call-affecting rules).
5. `npm test` — the per-op forwarding, gated-model, and frozen-list tests fail loudly if registration or event flow changed.
6. `npm run measure` and update the table in `README.md`.
7. Update the version above and the trim notes in this file.
